# sijk System

Административный Discord-бот для сервера sijk.

## Возможности первой версии

- `/warn`, `/warnings`, `/unwarn` и автоматические тайм-ауты;
- `/timeout`, `/untimeout`, `/kick`, `/ban`, `/purge`;
- логи удалённых и изменённых сообщений;
- закрытые логи модерации;
- панели Boosty/Twitch/YouTube/Telegram и Google Форм;
- настройка каналов и роли прямо из Discord.

## Запуск

1. Создайте приложение и бота в Discord Developer Portal.
2. На странице **Bot** включите `Server Members Intent` и `Message Content Intent`.
3. Добавьте бота на сервер со scope `bot` и `applications.commands`.
4. Задайте переменную `DISCORD_TOKEN` на хостинге. Токен нельзя добавлять в код или Git.
5. Необязательно задайте `DEV_GUILD_ID` равным ID сервера — команды появятся сразу.
6. Запустите `python bot.py`.

## Первичная настройка в Discord

Команды выполняет владелец или администратор:

1. `/setup staff` — выбрать роль `инстапик рейны`.
2. `/setup channels` — выбрать три созданных лог-канала.
3. `/setup forms` — добавить ссылки на Google Формы.
4. В нужных публичных каналах выполнить `/panel`.
5. Проверить результат через `/setup status`.

Роль бота должна находиться выше ролей участников, которыми он управляет. Категория логов должна быть скрыта от `@everyone`.

## Bothost

Загрузите папку как Git-репозиторий или архив. Главный файл — `bot.py`. Если панель предлагает Docker, используйте приложенный `Dockerfile`. Для постоянного хранения база создаётся в `data/sijk.sqlite3`; на Bothost при необходимости задайте `DATA_DIR=/app/data`.

## Проверка и ограничения версии 1.1

- Добавлены проверки реальных прав модератора и бота, а также иерархии ролей при наказаниях.
- Команды `/setup` и `/panel` требуют прав администратора на сервере.
- Формы должны вести на `docs.google.com` или `forms.gle`.
- Удаления и правки в настроенных лог-каналах не дублируются в логах сообщений.
- Приветствие через вебхук не дублируется ботом.
- Уведомления о стримах и новые записи в Google Таблице **не реализованы** в этой версии.
- Не выдавайте боту право Administrator без необходимости. Проверяйте сначала на тестовом сервере.
- Важное: SQLite-файл `data/sijk.sqlite3` должен храниться на постоянном диске. При пересоздании контейнера без volume данные пропадут.
