# SIJK CHECK — подключение через твой Google-аккаунт (OAuth)

**Новый Google-аккаунт и сервисный аккаунт не нужны.** Таблица остаётся приватной. Бот читает и добавляет записи через разрешение владельца Google-аккаунта.

## Однократная авторизация на своём компьютере

1. Открой Google Cloud Console под тем Google-аккаунтом, где хранится таблица. Создай проект или используй существующий.
2. Включи **Google Sheets API**. Настрой OAuth consent screen (Google Auth Platform): тип External, режим Testing и добавь **свою почту** в Test users. Если доступен Internal для Workspace, можно использовать его.
3. Создай OAuth Client ID типа **Desktop app** и скачай JSON с секретами клиента на свой ПК.
4. Установи зависимости из `requirements.txt`, затем запусти локально:
   `python scripts/sijk_check_google_auth.py /путь/к/client_secret.json`
5. Откроется браузер Google: войди в свой аккаунт и подтверди доступ к Google Sheets. Скрипт сохранит три значения в локальный файл `sijk_check_oauth_secrets.txt` рядом с JSON.
6. В секретах Bothost задай `SIJK_CHECK_GOOGLE_CLIENT_ID`, `SIJK_CHECK_GOOGLE_CLIENT_SECRET`, `SIJK_CHECK_GOOGLE_REFRESH_TOKEN`. При необходимости укажи `SIJK_CHECK_SPREADSHEET_ID` (по умолчанию используется текущая база SIJK SYSTEM).
7. **Не присылай эти секреты в чат и не добавляй их в GitHub.** Удали лишние копии файлов с токенами после настройки.

### Важно про Google OAuth Testing

У OAuth-приложений с типом External в режиме **Testing** refresh token для Google Sheets может истекать через **7 дней**. Для постоянной работы потребуется настроить публикацию OAuth-приложения в Production (это **не** публикует Google-таблицу), либо периодически повторять авторизацию. Публикация OAuth-приложения может потребовать дополнительной проверки Google в зависимости от выбранных разрешений. Не путать с доступом к таблице: доступ «Все, у кого есть ссылка» **не включаем**.

## Discord

1. Создай публичный канал SIJK CHECK и отдельный закрытый канал для проверяющих.
2. Администратор вызывает `/check_setup`, выбирает оба канала и роль `byba`.
3. В публичном канале вызови `/check_panel`.
4. Проверь `/check`, заявки, добавление доказательств и одобрение с оценкой и статусом.

Проверяющие с ролью `byba` могут принять решение только через бота. У них нет доступа к Google-аккаунту или прямого редактирования таблицы.

## Ограничения и тестирование

- **До подключения на Bothost сделай копию таблицы и резервную копию SQLite.** Сейчас ветка не тестировалась на реальном Discord.
- Бот добавляет записи в A:G, не перезаписывает уже существующие Riot ID. При сбое Google API дело остаётся в ожидании записи.
- Токен владельца позволяет приложению работать с таблицами от его имени. Это **более широкие полномочия**, чем доступ к одной таблице; держи токен в секретах и ограничивай доступ к хостингу.
- Google Sheets API не даёт транзакционной гарантии между проверкой существования Riot ID и добавлением строки; перед production требуется тестирование повторных и параллельных запросов.
- История переименований Riot ID — будущая отдельная функция.

**Не меняй production-бота на эту ветку до тестового запуска.**
