# SIJK CHECK — подключение Google Apps Script без Google Cloud

Этот вариант работает через **твой существующий Google-аккаунт**. Никаких сервисных аккаунтов, OAuth Client ID или банковской карты. **Сама таблица остаётся приватной.**

## 1. Сделай копию таблицы

В Google Sheets: **Файл → Создать копию**. Пока тестируем на копии или с готовым резервным экземпляром.

## 2. Вставь скрипт в таблицу

1. Открой нужную Google-таблицу SIJK SYSTEM.
2. Нажми **Расширения → Apps Script**.
3. Удали шаблонный код в `Code.gs` и вставь **полностью** содержимое файла [`apps_script/Code.gs`](apps_script/Code.gs) из этой ветки GitHub.
4. Сохрани проект. Он будет работать с таблицей по ID, указанному в начале скрипта. **Если тестируешь на копии, обязательно поменяй `SIJK_CHECK_SPREADSHEET_ID` на ID копии.**

## 3. Установи секрет доступа

1. В Apps Script открой **Настройки проекта (Project Settings) → Свойства скрипта (Script properties)**.
2. Добавь свойство с именем **`SIJK_CHECK_API_KEY`**.
3. Значение — **случайный секрет не короче 32 символов**, лучше 48–64 случайных символа, созданных менеджером паролей. Не используй обычный пароль.
4. Сохрани. **Никому не присылай секрет, не вставляй в исходники и не публикуй скриншот с ним.**

## 4. Опубликуй веб-приложение

1. Нажми **Развернуть (Deploy) → Новое развёртывание (New deployment)**.
2. Тип: **Веб-приложение (Web app)**.
3. **Выполнять от имени (Execute as): Меня (Me)**.
4. **Кто имеет доступ (Who has access): Все (Anyone)** — только если этот вариант доступен для твоего аккаунта.
5. Нажми **Развернуть** и пройди подтверждение разрешений Google на доступ к таблице.
6. Скопируй **Web app URL** вида `https://script.google.com/macros/s/.../exec`.

**Важно:** «Все» делает доступным **адрес веб-приложения**, а **не Google-таблицу**. Таблицу не нужно открывать «всем по ссылке». Но сам скрипт технически публично вызываем, поэтому секрет обязателен; любой, кто украдёт секрет и URL, сможет выполнять разрешённые операции от твоего имени. Держи их только в секретах хостинга.

Если Google не предлагает «Anyone» или запрещает развёртывание, этот способ для удалённого бота может не подойти — не обходи ограничение поддельными данными.

## 5. Подключи к Bothost

В переменных окружения/секретах бота:

- `SIJK_CHECK_SCRIPT_URL` — URL веб-приложения, заканчивается на `/exec`.
- `SIJK_CHECK_SCRIPT_KEY` — **тот же** секрет, что в свойствах скрипта.

В GitHub эти значения **не добавлять**. После изменения `Code.gs` нужно обновить версию развёртывания через **Manage deployments → Edit → New version**.

## 6. Discord

1. Создай публичный канал SIJK CHECK и закрытый канал рассмотрения.
2. Администратор вызывает `/check_setup`, выбирает оба канала и роль **byba**.
3. В публичном канале вызови `/check_panel`.
4. Проверь `/check`, жалобы, дополнение доказательств и одобрение с оценкой/статусом.

Только участники с ролью `byba` могут принимать решения через бота. Они **не получают** прямого доступа к Google-таблице.

## Что умеет веб-приложение

- `lookup`: по секрету возвращает **одну** запись по точному Riot ID; не отдаёт список игроков.
- `add`: по секрету добавляет новую строку в A:G, только если Riot ID ещё нет. Оценка от 1 до 10, статус из пяти вариантов, доказательства и комментарий.
- Нет методов удаления, массового экспорта, перезаписи существующих оценок или изменения доступа к документу.
- Для предотвращения одновременного добавления одного Riot ID используется блокировка Apps Script. Если запрос сорвался после фактической записи, повторная попытка найдёт уже существующую строку.
- Google-таблица **не публикуется**. Однако API-ключ даёт право выполнять `lookup` и `add` любому его обладателю; это не полноценная система авторизации Google для каждого пользователя.

## Перед production

Сделай резервную копию таблицы и SQLite. Код ещё не проверен на настоящем Discord/Apps Script; до тестов **не меняй работающего бота на ветку `feature/sijk-check`**.
